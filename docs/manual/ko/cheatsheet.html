한 줄로 보는 생애주기

install→ project create / add→ doctor→ tui / service→ ticket→ agent runs→ Human Review→ Done

설치와 첫 실행

git clone https://github.com/cskwork/oh-my-symphony.git && cd oh-my-symphony
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -e ".[dev]"
symphony project create "My App" --path ../my-app && cd ../my-app
symphony doctor ./WORKFLOW.md
symphony tui ./WORKFLOW.md

CLI

명령하는 일
symphony tui칸반 TUI 열기 (--tui와 동일)
symphony doctor실행 전 WORKFLOW.md 사전 점검
symphony board파일 칸반 보드 관리 (init/ls/new/mv/update/show/graph)
symphony service오케스트레이터를 백그라운드 서비스로 실행
symphony project독립 프로젝트 서비스 등록·실행
symphony hub여러 프로젝트를 모아 보는 허브 서버
symphony runs최근 실행 기록 출력
symphony release애플리케이션 릴리스 증빙 검증
symphony wiki-sweepdocs/llm-wiki 중복 슬러그·고아 문서 점검
자주 쓰는 전체 명령효과
symphony board init ./kanban파일 보드를 만들고 예시 티켓 DEMO-001.md를 넣는다
symphony board new TASK-1 "title"kanban/TASK-1.md 생성. 옵션: --priority 2 --labels backend,test --description "…" --blocked-by ID --agent-kind codex
symphony board ls --state Todo티켓 목록, 상태로 필터 가능
symphony board mv TASK-1 Blocked상태 강제 변경. 다음 폴 틱(poll tick, 주기적 조회 시점)에 다시 평가된다
symphony service start ./WORKFLOW.md --port 9999백그라운드 서비스 + 웹 보드. 이후 status / logs / restart / stop
symphony runs ./WORKFLOW.md --limit 5최근 실행 기록 (--issue ID로 필터)

웹 보드

항목내용
URLhttp://127.0.0.1:<port>/ (server.port 또는 --port). 루프백(내 컴퓨터 안) 전용
Pause / Resume실행 중 카드의 버튼. 해당 워커를 잠시 멈추거나 다시 돌린다
헤더 refresh오케스트레이터의 poll + reconcile을 즉시 실행한다
브랜치 드롭다운실제 로컬 git 브랜치. agent.feature_base_branch(새 브랜치 시작점), agent.auto_merge_target_branch(Done 머지 대상)
Bearer 토큰실행 전 export SYMPHONY_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')". 웹 앱은 첫 401 뒤에 토큰을 묻는다. 선택 사항

WORKFLOW.md 최소 구성

---
tracker:
  kind: file
  board_root: ./kanban
  active_states: [Todo, "In Progress", Verify, Document]
  terminal_states: ["Human Review", Done, Blocked, Archive]
agent:
  kind: claude          # codex | claude | gemini | agy | kiro | opencode | pi | prime-agent
  max_concurrent_agents: 1
server:
  port: 9999
---
키무엇을 바꾸는가
agent.kind기본 에이전트 CLI. 티켓 frontmatter의 agent_kind:로 개별 덮어쓰기 가능
agent.max_concurrent_agents동시에 도는 워커 수 (각자 자기 worktree 안에서)
tracker.active_states오케스트레이터가 에이전트를 투입하는 컬럼들
server.port웹 보드 + JSON API 포트. 블록을 지우면 HTTP를 끈다
agent.feature_base_branchsymphony/<ID> 브랜치의 시작점. 빈 값 = 호스트의 현재 브랜치
agent.auto_merge_target_branchVerify 게이트가 머지해 넣는 브랜치. 빈 값 = 기능 브랜치를 딴 원래 브랜치

티켓 상태

상태여기서 일어나는 일
Todo분류(triage) 후 In Progress로 보낸다. Acceptance Criteria가 있는 명확한 티켓은 모델 턴 없이 통과
In Progress계획 + TDD 구현 + 자기 검토. symphony/<ID> 브랜치 위에서
Verify리뷰 + QA + 머지 게이트. 기능 브랜치를 대상 브랜치에 머지해야 Document로 넘어간다
Document문서 + 위키 반영. 개입이 없으면 Done (S로 건너뛰기)
Human ReviewDone 전에 사람이 개입하거나 명시적으로 검토한다. TUI에서 c, 또는 웹 보드에서 승인
Done검증 완료. <ID>: <title> 커밋 하나로 남는다. a로 아카이브

문제가 생기면

doctor가 FAIL을 출력 — 그 줄이 가리키는 것만 고친다 (자리표시자 클론 URL → worktree 기본값 또는 : noop, CLI 누락 → $PATH에 설치). symphony doctor ./WORKFLOW.md 재실행. 종료 코드 1 = FAIL 있음, 2 = WORKFLOW.md를 읽지 못함.
워커가 종료되고 카드에 ↻ — agent.max_retries까지 간격을 늘려가며 자동 재시도. 마지막 오류는 symphony runs ./WORKFLOW.md --limit 5와 symphony service logs ./WORKFLOW.md에서.
에이전트가 몇 분째 조용함 — stall_timeout_ms 안에 진행이 없으면 워커가 취소된다. 무거운 레인만 agent.stall_timeout_ms_by_state: {Verify: 900000}으로 넓히고 log/symphony.log를 tail한다.
포트가 이미 사용 중 — doctor가 보고한다. --port N이 server.port를 덮어쓴다. symphony service status ./WORKFLOW.md로 점유한 서비스를 찾는다.
TUI가 조용히 꺼짐 — 실제 TTY(터미널)가 필요하다. 포그라운드 터미널에서 실행하거나, headless(화면 없이)로 symphony ./WORKFLOW.md를 돌리고 WORKFLOW-PROGRESS.md를 읽는다.
